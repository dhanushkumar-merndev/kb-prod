# Payroll

Apply `supabase/migrations/202609050001_payroll_simple_design.sql`, `202609050002_payroll_lock_reversal.sql` and `202609050003_payroll_calendar_month_days.sql` to the target Supabase environment before releasing this application change. The migration adds salary structures, payable-day snapshots and franchise-scoped payroll generation. Existing payroll amounts and paid history are preserved; old entries without day snapshots display “Unavailable”.

HR or the Director can save monthly components under **Salary setup**, then generate a draft for the selected month. Basic pay continues to come from Employee Records. Salary revisions have an effective month and carry forward automatically. Changes affect newly generated drafts; existing drafts retain their saved figures and audited corrections remain available in employee details.

Monthly staff are salaried for the whole calendar month, so weekly offs and holidays do not reduce pay. A day costs a monthly employee salary only when Attendance records it as `absent`, or when approved leave falls on it and the saved salary structure does not enable paid leave; approved paid leave outranks an absence marker on the same day. Payable days start at the joining date, so mid-month joiners are prorated. Daily, hourly and temporary workers are unchanged: they are paid only for days with approved or corrected attendance. Earnings and employer contributions are prorated by payable days divided by calendar days in the month. Configured employee deductions are prorated by period length. PF, ESIC, professional tax and TDS use saved amounts supplied by payroll staff; the application does not infer statutory rates. All four default to zero, and a zero component is never written, so PF and ESI produce no employee deduction and no employer contribution until someone enters an amount in Salary setup. Enabling them later is a data change only. Daily/hourly and completed-booking earnings retain the existing approved-work rules. Approved expenses are reimbursed once.

Gross salary excludes reimbursements. Net salary includes reimbursements and subtracts employee deductions/advances. Company cost is gross salary plus reimbursements and employer contributions. Reversed entries remain in history and CSV exports, but are excluded from summary totals and payslips. The Employee Payroll table shows reversed rows struck through and carries a totals row that matches the Summary and Payroll History cards, which use the same calculation.

The page displays **Draft → Review → Approved → Paid** while preserving the existing HR submission, Manager review, Director approval/payment and permanent-lock audit steps. Once a period is locked nothing in it can change: amounts, day snapshots and status are immutable, and a paid entry inside a locked period can no longer be reversed (`PAYROLL_PERIOD_LOCKED`). Reversal stays available while a period is paid but not yet locked. Payslips are available after approval as a printable HTML document that supports Indian-language names; open it and use Print to save a PDF. Payroll export downloads CSV.

Run `pnpm test`, `pnpm typecheck`, `pnpm lint` and `pnpm build`. The payroll integration tests run the production payroll SQL in isolated PostgreSQL/WASM with minimal Auth/franchise fixtures. They do not replace the full Supabase database suite (`pnpm supabase:test`) against a locally running Supabase stack.
